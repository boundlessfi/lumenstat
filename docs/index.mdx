Lumenstat measures how people use a Stellar project's website and API, and produces numbers that hold up when someone checks them. It sets no cookies, stores no IP addresses, keeps no API traces or request bodies, and refuses to count traffic that does not come from a real browser on a real network.

It runs as one shared service for the [Stellar Community Fund](https://communityfund.stellar.org), so every project is measured by the same pipeline and the same rules. A project's page views on Lumenstat mean the same thing as another project's page views.

## Why it exists

SCF funds projects in tranches, and reviewers need usage numbers they can rely on. Most analytics tools answer a different question: they are built to help one team understand its own visitors, with whatever tracking that team is comfortable with, and they count whatever arrives at the collect endpoint. A number from one of them cannot be compared with a number from another, and a script can inflate either.

Lumenstat is built for the comparison. Three properties make that work:

<AccordionGroup>
  <Accordion title="Private by construction" icon="eye-off">
    Visitor IP addresses are used in memory for a country lookup and a daily visitor hash, then discarded. The hash uses a random salt that is deleted after 48 hours, after which no one, including the operator, can link a stored record to a person. Query strings are stripped except `utm_*` tags. See [Privacy](/trust/privacy).
  </Accordion>
  <Accordion title="Hard to inflate" icon="shield-check">
    Every event passes four checks: it must come from a browser on the site's own domain, carry a proof of work computed by the tracker, come from outside known data-center ranges, and come from a network that is not sending an implausible number of new visitors. Events that fail are stored as flagged and never counted, so projects and operators can see attempts instead of absorbing them. See [Bot and inflation defense](/trust/bot-defense).
  </Accordion>
  <Accordion title="Verifiable" icon="badge-check">
    The tracker you embed lives at an immutable, versioned URL with a published integrity hash, and it rebuilds byte for byte from source. The code, the infrastructure and these docs are MIT licensed. See [Tracker supply chain](/trust/tracker-supply-chain).
  </Accordion>
</AccordionGroup>

## What it is built on

The web path is [Umami](https://github.com/umami-software/umami) v3.5.0 with a small set of documented patches, each behind its own switch. The API path is a standard [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/) and a small writer service. Data lives in PostgreSQL on servers in the European Union. The dashboard is built with the [Stellar Design System](https://github.com/stellar/stellar-design-system).

Lumenstat is built by [Boundless](https://www.boundlessfi.xyz) for the SCF request for proposals *Web and API Analytics for Stellar Ecosystem Projects*. The [roadmap](/project/roadmap) follows that proposal's milestones.
