The writer serves a read-only JSON API over the API metrics it stores: totals per project and a breakdown per route. The dashboard reads your API numbers through it. The writer has no public hostname: on the hosted service you read these numbers in the dashboard. The API itself is for self-hosters and for operators with access to the stack.

## Base URL

The writer is not on a public hostname. The Cloudflare Tunnel routes only `app.`, `t.` and `otlp.`, and `otlp.` only to the collector. The dashboard calls the writer over the stack's private network with an operator key and filters the results to your project on its server before anything reaches your browser.

| Where | Base URL |
| --- | --- |
| Inside the production Compose stack | `http://writer:8080` |
| Local development (`docker-compose.yml` in the repository root) | `http://localhost:8090` |
| Hosted Lumenstat | No public URL. Use the **API** page in the dashboard. |

The examples use `$WRITER_URL` for the base URL. The writer listens on the port in its `PORT` variable, 8080 by default.

## Authentication

Every request needs a read key in the `Authorization` header:

<ParamField header="Authorization" type="string" required>
  `Bearer` followed by a space and the read key, for example `Bearer scf_read_...`. The scheme is case-sensitive: write `Bearer` with a capital B.
</ParamField>

A read key has one of two scopes:

| Scope | Created with | Sees |
| --- | --- | --- |
| Operator | `key:create` without `--tenant`, or the `SCF_BOOTSTRAP_OPERATOR_KEY` variable | Every tenant |
| Tenant | `key:create --tenant <tenant id>` | Its own tenant only. Any other tenant ID returns 404, the same as one that does not exist. |

Read keys start with `scf_read_`, are shown once and are stored only as SHA-256 hashes. Each use updates the key's `last_used_at`. Issue and revoke them with the writer's CLI, from `apps/writer`:

```bash
npm run key:create -- --label "<who it is for>" [--tenant <tenant id>] [--days <n>]
npm run key:revoke -- <api key id>
```

`key:create` prints one JSON line with `apiKeyId`, `scope`, `tenantId`, `expiresAt` and `key`. `--days` sets an expiry. Without it the key does not expire.

`SCF_BOOTSTRAP_OPERATOR_KEY` is an operator key held in the writer's environment instead of the database. It is used only when it is at least 16 characters long, and it is compared with `timingSafeEqual`.

<Note>
  Issuing and revoking read keys from the dashboard's **Keys and health** page is planned for Milestone 2. See the [roadmap](/project/roadmap).
</Note>

The writer also has an operator-only control API under `/v1/admin/`, which the dashboard uses for tenants, ingest keys and enrollment. It is not covered here.

## Time range

Both endpoints take the same query parameters.

<ParamField query="range" type="string" default="24h">
  One of `1h`, `24h`, `7d` or `30d`. The window ends at `to`. An unrecognized value is treated as `24h`. Ignored when `from` is set.
</ParamField>

<ParamField query="from" type="string">
  Start of the window, inclusive, as an ISO 8601 timestamp such as `2026-11-06T00:00:00Z`. Defaults to `to` minus `range`.
</ParamField>

<ParamField query="to" type="string">
  End of the window, exclusive, as an ISO 8601 timestamp. Defaults to now.
</ParamField>

`from` must be earlier than `to`, and the window can be at most 800 days. Rows are per UTC minute, and a row is included when its minute starts inside the window.

## List tenants

`GET /v1/api-metrics/tenants`

Totals per tenant for the window. An operator key gets every tenant, including tenants with no data in the window, sorted by requests, most first, then by name. A tenant key gets a list with its own tenant only.

```bash
curl -s "$WRITER_URL/v1/api-metrics/tenants?range=7d" \
  -H "Authorization: Bearer $LUMENSTAT_READ_KEY"
```

## List routes

`GET /v1/api-metrics/tenants/:id/routes`

Requests, status codes and latency per service, method and route for one tenant. Status codes are summed into classes. At most 500 rows are returned, sorted by requests, most first. Routes with no requests in the window are not listed.

<ParamField path="id" type="string" required>
  Tenant UUID in lower case. Any other form returns 404 `not found`.
</ParamField>

```bash
curl -s "$WRITER_URL/v1/api-metrics/tenants/0b6f3c2e-8a41-4d3b-9f57-2c1e7a9d4b10/routes?from=2026-11-12T00:00:00Z&to=2026-11-13T00:00:00Z" \
```

## How the numbers are computed

- **One source per service.** For each service, if any rows in the window came from SDK metrics, only those rows are used. Otherwise the rows built from spans are used. A service that sends both is never counted twice.
- **Percentiles.** Bucket counts are summed over the window and across instances, then p50, p95 and p99 are interpolated linearly inside the bucket that holds the rank. A percentile in the overflow bucket, above 10 seconds, reads `10000`. See [Histogram buckets](/reference/otlp-ingest#histogram-buckets).
- **Error rate.** `errorRate` counts status codes of 500 and above. 4xx responses are not errors here.

## Errors

Errors are JSON with one field:

```json
{ "error": "invalid or revoked key" }
```

| Status | `error` | When |
| --- | --- | --- |
| 400 | `invalid time range` | `from` or `to` cannot be parsed, or `from` is not earlier than `to` |
| 400 | `time range too long` | The window is longer than 800 days |
| 401 | `missing bearer key` | No `Authorization: Bearer` header |
| 401 | `invalid or revoked key` | The key is unknown, revoked or expired |
| 404 | `tenant not found` | No such tenant, or a tenant key asked for another tenant |
| 404 | `not found` | Any other path or method, including a tenant ID that is not a lower-case UUID |
| 503 | `temporarily unavailable` | An unexpected server error |

Authentication runs before the time range is checked, so a request with a bad key and a bad range returns 401. Every response carries `cache-control: no-store`.

## Other writer endpoints

- `GET /healthz` returns `{"ok":true}` after a database round trip. It needs no key.
- `GET /dashboard` serves a single HTML page that calls the two endpoints above with a read key you paste in. The page keeps the key in the browser's session storage. It is meant for self-hosters and local development.
